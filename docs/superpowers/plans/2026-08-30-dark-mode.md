# Dark Mode Implementation Plan

## Goal

Add dark mode to the Online Donation Platform with a dark/light/system selector shown as a dropdown (icon + name) in the desktop header and inside the mobile menu. The user's choice persists in `localStorage`.

## Global Constraints

- Tailwind CSS v4 via the CLI. Source of truth: `core/static/src/app.css`. After editing source, rebuild with `npm run build` (regenerates `core/static/css/app.css`, which is committed).
- Use class-based dark mode: a `.dark` class on the `<html>` element, enabled with `@custom-variant dark (&:where(.dark, .dark *));`.
- Use semantic surface tokens so reusable component classes (`.card`, `.btn-*`, `.field-input`, `.chip`, `.progress-*`) flip automatically in dark mode. Only the handful of inline hardcoded colors get inline `dark:` variants.
- Theme preference stored in browser `localStorage` under the key `odp-theme` with values `"light"`, `"dark"`, `"system"` (default `"system"`).
- `system` resolves via `matchMedia('(prefers-color-scheme: dark)')` and live-updates when the OS theme changes.
- A small inline `<head>` script applies the theme class before paint to prevent a flash of wrong theme (FOUC).
- Match existing patterns: inline `<script>` in `templates/base.html` (as the existing `nav-toggle` script), and reuse the existing hover/focus dropdown pattern used by the user menu.
- No Django model/view/migration changes. Theme toggle is client-side only. Existing test suite must remain green.
- The design tokens are branded: `porcelain` (page bg), `ink` (primary text), `pine` (primary brand, buttons), `marigold` (accent/highlight), `rose` (destructive). Preserve the brand in dark mode (don't shift hue; adjust lightness/contrast only).

## Design Summary

Light palette stays as-is. Dark palette (`.dark` block):

- Page background (`porcelain`) → very dark green-tinted slate, e.g. `oklch(16% 0.015 160)`.
- Primary text (`ink`) → light porcelain, e.g. `oklch(92% 0.01 160)`.
- Surface token (used by `.card`, inputs, dropdowns, mobile menu) → `oklch(20% 0.015 160)`.
- Muted surface token (used by `pine-50` panels/`pine-100` chips/rails) → `oklch(24% 0.02 158)`.
- Border soft (used by `pine-100` borders) → `oklch(26% 0.02 158)`.
- Primary buttons (`pine-700`): raise lightness for contrast on dark, e.g. primary fills become `pine-500`; `pine-600` text/borders become lighter (`pine-400`/`pine-300`) for readability.
- `marigold` accent stays; `rose` destructive shifts slightly lighter for contrast.
- `text-white` on colored fills (buttons, active chips) stays white — those fills remain dark-enough in dark mode.

The key reusable component classes get tokenized so they flip:
- `.card` → `bg-surface` (was `bg-white`).
- `.btn-ghost` / `.btn-danger-ghost` → `bg-surface border-border-soft` (was `bg-white border-pine-100`).
- `.field-input` → `bg-surface border-border-soft` (was `bg-white border-pine-100`), placeholder color flips via token.
- `.progress-rail` → `bg-pine-100` (overridden per mode).

## Task 1 — CSS tokens + dark variant in `core/static/src/app.css`

Edit `core/static/src/app.css`:

1. After `@import "tailwindcss";` add:
   `@custom-variant dark (&:where(.dark, .dark *));`
2. In `@theme` add semantic surface tokens:
   - `--color-surface`
   - `--color-surface-muted`
   - `--color-border-soft`
   mapped to the light-mode values (surface near-white, surface-muted = pine-50, border-soft = pine-100).
3. Add a `.dark { ... }` block overriding: `--color-porcelain`, `--color-ink`, `--color-pine-50/100/400/500/600/700/900`, `--color-surface`, `--color-surface-muted`, `--color-border-soft`, `--color-rose-500/600` to the dark-mode values above. Keep `marigold` and `pine`-brand hue identity.
4. Update `@layer components` so dark mode works:
   - `.card` → `@apply ... bg-surface ...`
   - `.btn-ghost` → `@apply ... bg-surface border-border-soft ...`
   - `.btn-danger-ghost` → `@apply ... bg-surface border-rose-500/30 ...`
   - `.field-input` → `@apply ... bg-surface border-border-soft text-ink placeholder:text-ink/35 focus:border-pine-500 ...`
   - `.progress-rail` → keep `bg-pine-100`.
5. Ensure `@layer base` body uses `bg-porcelain text-ink` (already does) so it flips.

Do not add any code comments.

- `core/templates/core/includes/_pagination.html` lines 8, 16, 24 → `bg-surface` instead of `bg-white`.

- `core/templates/core/includes/_campaign_card.html:8` category chip `bg-white/90` overlays a deterministic cover gradient (always dark) → keep light overlay in both modes to remain readable on the gradient. No change needed unless a `dark:` tweak is warranted; keep `bg-white/90 text-pine-700`.
- `core/templates/core/includes/_cover_banner.html:3` chip `bg-white/70` overlays cover gradient → keep as-is (light-on-dark gradient in both modes).
- `base.html`: header `border-pine-100` and `bg-porcelain/85` already use tokens and flip automatically; the dropdown panel (`bg-white` line 46) and mobile menu (`bg-white` line 104) → `bg-surface`.

Do not add any code comments. Rebuild Tailwind after template edits only if new utility classes were used.

## Task 3 — Theme dropdown UI + JS in `templates/base.html`

Add the dark/light/system selector.

1. **In `<head>`**, before the stylesheet link, add an inline script that prevents FOUC:
   - Reads `localStorage['odp-theme']` (default `"system"`).
   - For `"system"`, use `matchMedia('(prefers-color-scheme: dark)').matches`.
   - Applies/removes `document.documentElement.classList` `dark`.
   - Wrap in an IIFE.
2. **Drop-down control** following the existing hover/focus dropdown pattern (like the user menu, `group` class):
   - A trigger button (icon + current mode name) with `aria-haspopup`, `aria-expanded`.
   - A panel with three options: Light, Dark, System — each an icon + label — plus a checkmark on the active one.
   - Icons: use inline SVGs (sun for light, moon for dark, monitor/auto for system).
   - On selecting an option: set `localStorage['odp-theme']`, re-apply the `.dark` class, update the trigger label + icon + active checkmark, close the dropdown.
3. Place the control:
   - In the desktop nav (`hidden md:flex`), before the user menu.
   - Inside the mobile menu `#mobile-menu` so it's reachable on mobile.
4. **Live `system` updates**: a `matchMedia('(prefers-color-scheme: dark)')` listener that, when the stored mode is `"system"`, toggles `.dark` in response to OS changes.
5. Match reusable component classes (`.btn-ghost` for the trigger, `.card`-style or existing dropdown classes for the panel).

Do not add any code comments. Keep JS consistent with the existing inline `nav-toggle` script style (plain JS, already in `base.html`).

## Task 4 — Rebuild CSS and verify

1. Run `npm run build` to regenerate `core/static/css/app.css` from the edited source.
2. Run `uv run python manage.py check` — sanity check passes.
3. Run the existing test suite (SQLite, per AGENTS.md DB note) — confirm remains green: `uv run python manage.py test`.
4. Manual sanity: confirm the dropdown markup/JS references correct element IDs and that server-side template rendering is unaffected (e.g., `uv run python manage.py runserver` optional; template syntax check via `check`).
